# v1.5.0 Release Plan — Native Menu, Central Rendering, SDK 0.0.15

Status: IMPLEMENTED 2026-09-12 (all three phases; ship checks below). Deviations: true
zOrder crop skipped (consult consensus: low value, current rendering proven on device —
revisit only with a device-gate pass); resume-glance frame deferred (pace groundwork landed). Baseline: v1.4.6 working tree (uncommitted), 140/140 tests green.
**Ship shape: ONE release (v1.5.0)** — no intermediate 1.4.7/1.4.8 portal releases. Safety comes
from internal phase ordering + dual-write transition formats (§2), not from release boundaries.

## 0. Theme and goals

1. **Adopt the 0.0.14+ platform capabilities**: native contextual menu (`menuObject`),
   `textColor` brightness, long-press-safe event handling.
2. **Fix the rendering core first**: central render planner, upgrade-based page turns,
   serialized SDK effects — the prerequisites that make menu adoption safe.
3. **Interruption recovery**: pause-and-rewind Flow, resume glance, chapter time-left.
   Reading quality over feature count.

Non-goals (explicit cuts, do not revisit without new evidence): app-side long-press quick menu,
zOrderIndex crop rewrite, book-level ETA, TTS, book covers, sleep timer, reading stats,
night mode (OS owns brightness), RTL/CJK.

## 2. Phase ordering inside the single release (internal milestones, not releases)

All phases land in v1.5.0, in this strict order, each gated by build + full tests (+ device
checks where marked). No phase ships to the portal separately; device verification uses QR
sideload / packed `.ehpk`, which does not require a portal release.

**Rollback rule (replaces the "staged releases" safety argument):** every transition format is
dual-written for the life of 1.5.x — v2 positions ship with a v1 mirror, the split library
storage keeps the legacy single-blob key in sync. If 1.5.0 must be pulled, users reverting to
1.4.6 lose nothing: positions degrade to the last v1-mirrored value and the bridge library
survives intact. Removing the mirrors is a 1.6 cleanup, gated on 1.5.0 being stable in the field.

### Phase 1 — data safety (on SDK 0.0.10)
1. Commit the pending v1.4.6 tree.
2. Position migration legacy→content ID: when opening a book whose stored ID is
   `makeBookId(filename, title)`-shaped and a row is re-keyed to a content ID (`db.ts`
   `putIndexedDB`), copy `${STORAGE_KEY_POSITION}-${oldId}` / flow variant to the new key.
3. Stop writing the title-lane position key for content-ID books (`position-store.ts`).
4. L3 keys written only when a book opens; page-turn saves debounced (flush on exit/GO_BACK);
   check `setLocalStorage` result and surface persistent failures.
5. Split bridge library storage: `epub-book-index` (metadata list) + `epub-book-data-<bookId>`
   (base64 payload per book). Read-compat with the single-blob key; visible "storage full"
   error when a write returns false.
6. Serial event/SDK queue: latest-wins for visible renders, FIFO for persistence, one
   rejection must not wedge the queue.
7. `refreshCurrentView` covers every `ViewState` (bug: mainMenu/settings/settingEditor land
   on the wrong screen today).
8. Deduplicate `getSavedPosition` / `restorePagedPosition` into one position store.

### Phase 2 — reading feel
1. **Position format v2** (required before any pagination change; pretext in 1.5.x depends
   on it):
   ```ts
   { v: 2, chapterIndex: number, offset: number, // offset into cleaned chapter text
     paginationVersion: number, pageIndexHint?: number }
   ```
   Write v2 (+ v1 mirror, dual-written through 1.5.x); read v1 → derive offset from current pagination.
2. Page turns via `textContainerUpgrade` (no rebuild when container topology unchanged).
3. Tap in paged mode hides/shows the footer by clearing/updating the footer container only —
   no repagination, no position drift.
4. True text-height crop: visible text container shorter + full-screen invisible capture
   container declared first (the proven `rebuildSlots` pattern) — no zOrderIndex.
5. Metrics adapter module (`src/text-metrics.ts`) wrapping `even-toolkit/pretext`; footer
   truncation + menu box widths migrate to it. Body pagination stays char-based until 1.5.x.
6. Toolkit 1.7.7 + regenerated `patches/even-toolkit+1.7.7.patch` (gesture diff empty — low risk).

## 3. v1.5.0 feature specifications

### 3.1 Native contextual menu (`menuObject`)

Menu payloads (static verb labels only — labels never update without re-declaration):

| View | Items (id, label) |
|---|---|
| Paged reading | 1 `Contents`, 2 `Switch to Flow`, 3 `Bookmark page`, 4 `Main menu` |
| Flow reading | 1 `Faster`, 2 `Slower`, 3 `Contents`, 4 `Switch to Paged`, 5 `Bookmark page`, 6 `Main menu` |

Rules:
- **No `Exit` item** — the OS supplies `Close [app name]`.
- Not registered in list views (`mainMenu`, `bookPicker`, `chapterList`, `settings`,
  `settingEditor`, welcome) — the OS default menu is fine there.
- Constraints: ≤10 items, `itemID` non-zero unique uint32, `itemName` ≤32 UTF-8 bytes
  (16 Cyrillic chars), payload order = render order.
- **Every reading-view rebuild carries the menu.** A rebuild without `menuObject` clears it.
  The central render planner enforces this (single call site, not the current 5+).
- `menuItemClickEvent` is routed **before** `mapGlassEvent` (it does not flow through the
  gesture pipeline). Stale-click guard: menu-generation token incremented per view entry;
  clicks with a stale token are dropped.
- Lifecycle reducer (pure, unit-tested):
  ```text
  active      + FOREGROUND_ENTER → overlayOpen   (no rebuild, no flush)
  overlayOpen + menuItemClick    → pendingAction (executed after matching EXIT)
  overlayOpen + FOREGROUND_EXIT → active
  active      + FOREGROUND_EXIT  → backgrounded  (pause flow, flush)
  backgrounded+ FOREGROUND_ENTER → active        (restore view, no rebuild unless tested)
  ```
  Unknown event order (exit→click→enter vs exit→enter→click) must both work — the reducer
  keys on state, not sequence assumptions. Menu open pauses Flow; Flow stays paused after
  dismissal unless the action resumed it.
- Device gate (see §8): if testing shows the OS does not restore the page under the menu,
  add a `textContainerUpgrade` (not rebuild) on ENTER.

### 3.2 `textColor` brightness hierarchy

- Body text: 4. Footer/status bar: 3. Dim hints ("(No recent book)", welcome hints): 3.
- Optional `Text brightness` setting (1–4, default 4) applying to body text; 0 excluded
  (may render invisible), clamp + `loadSettings` migration.
- Applies on create/rebuild AND `textContainerUpgrade` (clock ticker must pass `textColor`
  through, else the footer brightens on first rollover).
- Container-rule guard: `textColor` is 0–4 while `borderColor` stays 0–15.

### 3.3 Long-press handling (defensive only)

- Keep ignoring events 9/10 for navigation (toolkit 1.7.2/1.7.7 `mapGlassEvent` returns null).
- Optional non-essential use: `LONG_PRESS_EVENT` in flowReading pauses Flow (safety stop).
  No feature may depend on long-press (OS menu owns tap+hold).

### 3.4 Interruption recovery

- Pause Flow on: menu open, `FOREGROUND_EXIT`, `SYSTEM_EXIT`, and
  `onDeviceStatusChanged` wear-state loss if the SDK exposes it (verify field name in 0.0.15
  types). Never auto-resume; leave a clear paused frame.
- **Auto-rewind on resume**: when Flow resumes (tap after pause, or Continue), set
  `flowWordIndex` back to the start of the current sentence, or −8 words when the sentence
  start is farther than 8 words. Fixed default, no setting.
- **Sentence rewind while running**: flow swipe up/down = back/forward one sentence
  (replaces chapter-jump-per-swipe; temple touches are the most common accidental input).
  Needs a pure sentence tokenizer (abbrev/decimal-aware enough for books; unit-tested).
- **Resume glance**: on Continue, the footer/first frame shows
  `Ch C · N% · M min left` (percent = position v2 offset/length; minutes = words remaining
  in chapter ÷ rolling pace).
- **Stop after chapter**: flow-menu item (`menuObject` is static — implement as a
  check-at-chapter-end flag set via a menu item, or defer to 1.5.x if the static-label
  constraint makes UX awkward).

### 3.5 Chapter time-left in footer

- Rolling pace = words read in the last 5 minutes of active flow time (ephemeral, not
  persisted). Footer: `HH:MM Ch C/T Pg P/N [bar] Mm left` only when pace data exists —
  no fabricated numbers. Width-checked via the metrics adapter (32-byte/px budget).

### 3.6 Single quick bookmark

- `Bookmark page` marks the current position (per bookId, bridge key `epub-bookmark-<bookId>`,
  position v2 shape). `Contents` lists `Resume` and `Bookmark` as the first two entries of
  the existing chapter list view (bookmark row pinned at top when present). Managing/removing
  bookmarks stays on the phone UI. Overwrite semantics: one bookmark per book (v1).

## 4. Architecture work (required for 1.5.0 features)

Done as part of the features, not a separate refactor release. Target: `even-client.ts`
coordinates only (~600 lines).

1. **Central render planner** — decides `rebuild | upgrades | no-op` from (view, layout,
   content) signatures; owns `menuObject` injection, `textColor`, capture-container count
   validation, `notifyTextUpdate → resetGestureState` ordering (consistent everywhere),
   rebuild return-value checks (a `false` must not advance app state).
2. **Lifecycle reducer** (§3.1) — pure module `src/lifecycle.ts` + tests.
3. **Serial SDK executor** — adopt `createSerialExecutor` for all bridge display + storage
   lanes (Phase 1 #6).
4. **Per-view screen table** — `Record<ViewState, ScreenSpec>` replacing the if/else chains
   in gesture dispatch and `refreshCurrentView`; TypeScript exhaustiveness removes the
   missing-view bug class.
5. **Pure paginator** — `paginateText(text, layout, measure)` signature; no module-global
   hyphenator/wide-glyph state (prerequisite for the 1.5.x pretext swap and caching).
6. **`OpenBook` identity** — one object `{ book, bookId, filename }` replacing the three
   parallel fields.
7. **Flow timer module** — extraction of the tick scheduler/`flowTick` block.
8. **Versioned storage envelopes** — one canonical `epub-last-book` JSON record (title,
   bookId, filename, position v2) with legacy three-key reads retained through 1.5.x.

## 5. Data model and migrations (all versioned)

| Store | Change | Migration |
|---|---|---|
| Positions | v2 `{v, chapterIndex, offset, paginationVersion, pageIndexHint}` | read v1 → offset derived from current pagination; write v2 + v1 mirror through 1.5.x |
| Last-book meta | single `epub-last-book` record | legacy 3-key reads retained; write both until 1.6 |
| Settings | + `textBrightness` (1–4, default 4) | absent → default; clamp on load |
| Bookmarks | `epub-bookmark-<bookId>` position v2 | new |
| Library | index + per-book keys | Phase 1; legacy single-blob key dual-written through 1.5.x |

Test matrix: fresh install; 1.4.6→1.5.0 upgrade (incl. rollback to 1.4.6 with dual-writes in
place); v2↔v1 position round-trip; corrupt/partial
records; bridge write returning `false`; concurrent saves during flow ticks.

## 6. Testing plan

Unit (Node native runner, extends the existing 140):
- Render planner: rebuild/upgrade/no-op per (view, layout, content) signature; menu present
  on every reading rebuild, absent elsewhere; capture-count == 1; rebuild `false` handling.
- Lifecycle reducer: all sequences from §3.1, both event orders, flow running/paused.
- Menu payload builder: IDs unique/non-zero, ≤10 items, 32-byte labels (Cyrillic case),
  stale-generation rejection.
- Position v2: conversion from v1, offset round-trip across pagination changes, footer
  toggle, text-height change, re-upload re-key.
- Sentence tokenizer: 9 languages spot checks, decimals, abbreviations, quotes.
- Pace/time-left math; brightness clamp/migration; storage envelopes.

Integration: recording fake bridge (scriptable `false`/reject/slow responses) + node
`mock.timers` — tests read as "script of events → list of SDK calls". No jsdom for
glasses-side logic; jsdom only for `main.ts` companion UI if needed later.

Simulator 0.9.5 automation: `long_press`/`long_press_release` inputs, menu open→item→close
sequences, `textColor` rendering, screenshot diffs for the crop change.

## 7. Performance budget

- Repagination: full-book paginate on 1 MB EPUB ≤2 s on the WebView (measure; cache pages
  per `(bookId, paginationVersion)` once pretext lands).
- Page turn: `textContainerUpgrade` ≤150 ms end-to-end (was rebuild + 5 writes).
- Flow tick at 600 WPM (100 ms): must not overlap renders (serial executor), no drift.

## 8. Device verification (mandatory gates, in order)

1. 0.0.14/0.0.15 events arrive: LONG_PRESS/RELEASE payloads, `eventSource` present.
2. Does the OS default menu swallow tap+hold while a custom `menuObject` is registered?
3. Event order around menu: open/item/close sequences on hardware.
4. Does the OS restore the page under the menu after close? (decides ENTER behavior)
5. Does a registered menu survive `textContainerUpgrade`? (decides page-turn + menu combo)
6. Upgrade-based page turns: phantom-scroll timing, first-gesture-after-upgrade.
7. Brightness: footer level 3 legible outdoors; level 2+ visibly distinct.
8. Beta `.ehpk` on 2.2.10 host: full lifecycle (background/foreground, exits, Continue).

Simulator results never substitute for gates 1–7.
